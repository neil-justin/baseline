# O*NET all-36 enrich · offline snapshot + diff (extraction-time evidence — USER REVIEW ONLY)

**What this is.** One offline snapshot of the O*NET Web Services API v2 for this catalog's extraction-time enrich pass (ADR 0004 refresh ritual / ADR 0005 Model C §1): raw JSON pulled from `https://api-v2.onetcenter.org/` on 2026-11-02 for every O*NET-SOC occupation anchor that the catalog fixtures themselves record, pinned to the database version the API itself served, plus a field-by-field diff of that snapshot against what `lib/fixtures/catalog.ts` + `lib/fixtures/rowspec*` currently claim. Nothing here is applied: no fixture, engine, or e2e file was touched, and every status in the diff is a recorded fact for the user to rule on — the O*NET version pin the fixtures have been waiting on (the audit track's Row-11 tool-names placeholder among them) is now receivable as evidence.

**How it was produced.** The 36 tracks were extracted from `lib/fixtures/catalog.ts` (11 IT + 9 Business + 10 Accounting + 6 Office) and cross-checked against every O*NET-SOC anchor code in `lib/fixtures/rowspec/**` — that yields 18 distinct provenance-keyed codes covering 21 tracks; 15 tracks record no O*NET anchor (their rows are [PSF]/[TESDA]/[PSOC]/[NACE]-sourced) and no code was guessed for them. The exact routes came from the API's own published OpenAPI spec (`evidence/openapi.json`, fetched first, unauthenticated): per code the informational payload (`/online/occupations/<code>`) and the technology-skills sub-resource (`…/details/technology_skills`), plus the three further documented sub-resources the fixtures' claims engage (`details/tasks`, `details/skills`, `details/work_activities`), were pulled with the `X-API-Key` header loaded from `.env.local` in-process by `pull.mjs`/`paginate.mjs` (the key is never printed or written anywhere), 500 ms throttle between requests, single 1.5 s-backoff retry on 429/5xx only, and every documented `next` pagination page followed to the served `total` — 284 requests, all 200. Raw response bytes are stored **unedited** under `pulls/` with the exact request URL burned into a sibling `.url.txt`; receipts (URL, status, bytes, ms, attempts) live in `manifest.json`, which also copies the version strings verbatim from the API's `/about/` resource: **O*NET 31.0** (api_version 2.0.0, taxonomy O*NET-SOC 2019). Mechanical-attribution notes recorded rather than silently resolved: plain `Source-verbatim:` descriptor quotes on [O*NET]-tagged rows (opsanalyst/purch/events) were attributed to the role's single anchor, and two rows whose claims cite a different occupation's code than the role's anchor (treasury's Reconcile row → 43-3031.00) were compared against the code the fixture itself cites and labeled as such in the row line; `13-2051.00` (fin) serves `total: 0` for skills and work-activities at this pin — an API-side gap recorded, not substituted.

**How to read the diff.** Open `diff-log.md`: §0 states the derivation facts and endpoint gaps, then each of the 36 tracks gets a section (catalog order) whose per-anchor block compares our claims with the served data across five layers — occupation titles, task texts (each rowspec `"…"` quote and each `task as printed` row name against the served tasks list, task id + importance cited), work-activity attributions (name/description/importance), essential-skills pairings, and the audit Row-11 technology-skills pin (all 37 served categories with their example tool names, so the "individual tool names stay UNQUOTED until the version pin" placeholder can be ruled on). Every delta is marked MATCH / DIFFERS / PRESENT-ONLY-IN-OURS / PRESENT-ONLY-IN-ONET / NO-OUR-ROW with both texts printed adjacently — MATCH (228 claim spans) means the fixture claim survives normalization against the pinned snapshot; DIFFERS (14 charted plus 19 title-level display pairs; nearest served counterpart printed) means the claim's counterpart is absent at O*NET 31.0; §37 totals the markers per granularity. Treat it as input to the refresh-ritual review, not as a change list: no fixes, recommendations, or tier moves are encoded here — the user reviews the diff; a new catalog release ships it (ADR 0004). Unrelated pre-existing working-tree state observed during the pass (`next-env.d.ts` carrying a `next dev`-regenerated `…/.next/dev/…` import-path change) was left exactly as found — not produced, staged, or reverted by this run, and nothing outside `research/onet-enrich/` was written.
